# 문의 기능 운영

- 사용자 문의와 답변은 `support_tickets`에 저장한다. 사용자는 본인 문의만 볼 수 있고, 등록된 문의 관리자만 전체 문의를 조회하고 답변을 쓸 수 있다.
- 문의 관리자 권한은 `support_admins`에 해당 Auth 사용자 UUID를 추가할 때만 부여된다. 사용자는 이 테이블을 직접 수정할 수 없다. 관리자는 대시보드에서 커플 구성원 표시 이름, 커플 생성일, 저장된 일정·사진 수와 최근 14일 기록 생성량을 볼 수 있다. 대시보드는 사진 원본이나 경로, 일정 내용을 제공하지 않는다. Supabase 프로젝트 관리자 권한도 부여하지 않는다.
- 관리자 화면은 앱 주소 뒤에 `#admin`을 붙여 접속한다. 일반 로그인 화면에는 링크가 표시되지 않는다. 주소를 숨기는 것 자체는 보안 수단이 아니며, 로그인 후 데이터베이스에서 관리자 권한을 확인한다. 고객의 문의와 커플 정보는 개인정보일 수 있으므로 관리자 계정과 Supabase 접근 권한을 최소화한다.
- 문의 삭제는 사용자 문의 내역과 답변도 영구 삭제한다. 관리 화면에서 결과를 명시하고 확인한 경우에만 삭제한다.
- 활동 그래프는 저장된 일정·사진의 생성일만 집계하므로 삭제된 기록은 포함하지 않으며 접속 시간·방문 횟수를 의미하지 않는다.
- 문의함은 최근 문의부터 100건씩 표시하며 새로고침 버튼으로 최신 내용을 다시 불러온다. 답변 알림은 자동 발송하지 않으며, 사용자는 설정의 문의하기에서 답변을 확인한다.
- `20261117000000_support.sql`은 운영 프로젝트 SQL Editor에서 적용했다. 적용 전과 후에 롤백되는 테스트 데이터로 사용자 간 문의 격리, 권한 상승 차단, 관리자 답변, 사진 접근 제한을 검증했다. SQL Editor로 적용한 프로젝트에는 CLI 마이그레이션 이력이 없을 수 있으므로 마이그레이션은 재실행 가능하게 작성했다.
- 권한 검증은 `supabase/tests/support_rls_check.sql`을 테스트 환경에서 실행한다. 실패 시 배포하지 않는다.
- 대시보드 추가 권한과 삭제 정책은 `20261125000000_admin_dashboard.sql`로 적용하고, `supabase/tests/admin_dashboard_rls_check.sql`로 검증한다. 이 검증은 테스트 데이터를 롤백한다.
