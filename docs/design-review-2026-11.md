# MORO 화면 개선 — 2026-11-11

방향: Editorial greeting (design-taste-frontend, seed 747629987). 기존 파비콘의 라벤더·블루와 Pretendard를 유지했다. 별도 이미지나 폰트는 추가하지 않았다.

홈은 두 사람의 함께한 일수와 다음 기념일을 중심으로 오늘의 일정, 이번 주를 배치한다. 캘린더는 선택한 날의 할 일을, 앨범은 함께 남긴 사진을, 설정은 프로필·앱 설정·계정 작업을 구분해 보여준다. 데스크톱은 1080px 콘텐츠를 624/424px 두 열과 32px 간격으로 나누고, 모바일은 20px 여백과 하단 네 탭을 유지한다.

## 변경

- 카드·글자 크기·숫자 정렬·버튼 터치 영역을 공통 테마로 정돈했다.
- 홈의 진한 그라데이션을 라벤더 면으로 바꾸고 기념일 정보를 두 칸으로 정리했다. 사용자 배경 사진에는 가독성을 위한 중성 오버레이를 유지한다.
- 캘린더 추가 버튼을 상단으로 옮겨 목록/시간표를 가리지 않게 했다. 날짜 선택 테두리 반경은 4px 유지.
- 데스크톱 설정은 설명과 조작 영역을 나누며, 앨범은 사진을 5열로 보여준다.
- 탭별 스크롤 위치를 보존하고 화면 전체 등장 애니메이션을 제거했다.
- 아이콘을 작은 SVG로 교체하고 애니메이션 라이브러리를 제거했다. 사진 편집기는 열 때만 다운로드한다.
- 앱이 준비되는 즉시 시작 화면을 닫는다. 로딩 뼈대는 새 레이아웃에 맞추고 쉬머를 제거했다.
- 날씨 효과를 transform으로 이동시키고, 비활성 탭/백그라운드에서는 중지한다. 날씨 조회 실패 시 1분 동안 재요청하지 않는다.
- 앨범 월별 그룹화 시 배열을 매번 복사하지 않는다.

동일한 프로덕션 빌드 출력 기준 전체 JavaScript 청크의 gzip 합계는 약 294.95KB에서 261.46KB로 11.4% 감소했다. 빌드 대상 모듈은 1,970개에서 972개로 줄었다. 전송량·로딩 시간의 실기기 측정치는 아니며, 페이지별 지연 로딩 여부에 따라 실제 다운로드량은 달라진다.

## 검증

`cd web`에서 `npm test`, `npm run build`, `npm run lint` 실행. 린트는 오류 없이 완료하며 기존 React 컴파일러/개발 갱신 관련 경고는 남아 있다.

Chrome의 390/768/1440px 화면에서 홈·캘린더·빈 앨범·설정과 영문 다크 홈을 캡처했다. 브라우저 상호작용 검사에서 탭 이동, 스크롤 복원, 일정 입력창, 시간표 토글, 언어 전환, 지연 로드한 사진 편집기를 확인했다. 이미 방문한 탭을 1분 이내 다시 오갈 때 fetch 요청 수가 늘어나지 않았고 콘솔 예외도 없었다.

검사는 실제 컴포넌트와 개발용 샘플 데이터를 사용했다. 운영 계정의 로그인·업로드·푸시 전송 검증을 대신하지 않는다.

화면 검사 예외:
- `palette-purple`, `glass`: 사용자가 지정한 브랜드 및 내비게이션의 유리 효과.
- `no-title`: 검사기가 숨겨진 홈 탭의 첫 h1을 선택하는 오류. 현재 보이는 탭의 h1은 별도 검사했다.
- `hero-void`: 빈 앨범의 의도된 첫 사용 상태. 없는 사진을 채우지 않았다.
- `no-data-hue`: 적은 일정이 있는 실제 달력을 큰 차트로 오인한 항목. 일정 색상과 오늘 표시는 유지한다.
- 소스 검사에서는 사용자 사진 위의 중성 오버레이, 비·눈 입자 패턴을 허용한다. 날짜의 0 채우기와 단일 내비게이션 블러 경고는 의도된 사용이다.

자체 시각 검토: 정보 우선순위 8/10, 일관성 8/10, 반응형 8/10. 제목과 숫자 정렬, 데스크톱 공간 활용, 버튼 겹침은 개선했다. 실제 사진이 많은 앨범과 긴 일정 이름이 밀집한 달력은 운영 데이터로 추가 확인할 수 있다.

## 로컬 미리보기

`npm run dev` 실행 후 `/design-preview.html` 접속. `?tab=1` 캘린더, `?tab=2` 빈 앨범, `?tab=3` 설정, `?mode=dark&language=en` 영문 다크 홈. 프로필 이름·시작일·세 개의 일정은 테스트 데이터이며 제품 데이터에 저장하지 않는다. 미리보기는 모든 fetch를 가로채고 실시간 구독을 모의 처리한다. 프로덕션 빌드에는 이 HTML 진입점을 포함하지 않는다.
